# LLM Recommendation Data Preparation

This directory contains scripts for preparing training data for LLM-based recommendation systems.

## Overview

Converts user-item interaction sequences into LLM-friendly prompt format for fine-tuning. Each sample contains:
- User's purchase history with item titles and reviews
- Expected next item as target output

## Data Format

### Input Files
- `All_Beauty.jsonl`: Raw review data from Amazon Beauty dataset
- `item_titles_unique.json`: Unique condensed titles for each item (generated by Qwen3-1-7B)

### Output Files

| File | Description | Samples |
|------|-------------|---------|
| `train.json` | Training samples | 6,682 |
| `val.json` | Validation samples | 4,548 |
| `test.json` | Test samples | 4,548 |
| `stats.json` | Dataset statistics | - |

### Sample Format

```json
{
  "prompt": "User's purchase history:\n1. \"Item Title\" (Rating: 5) - Review: Great product...\n2. ...\n\nBased on the user's interaction history, predict the next product they would be most interested in purchasing.\n\nNext product:",
  "target_item_id": "B00XXXXXXXX",
  "target_title": "Expected Item Title",
  "user_id": "USERXXXXXXXXXX"
}
```

### Prompt Template

```
User's purchase history:
1. "[Item Title]" (Rating: X) - Review: [Review text truncated to 150 chars]
2. "[Item Title]" (Rating: X) - Review: [Review text]
...

Based on the user's interaction history, predict the next product they would be most interested in purchasing.

Next product: [Expected output]
```

## Data Split Strategy

Follows the same chronological split as vanilla SASRec:

- **Test**: Last item in sequence (all previous items as history)
- **Validation**: Second-to-last item (all items before that as history)
- **Train**: Sliding window on remaining items

## Filtering Criteria

- Minimum sequence length: 3 items
- Minimum item frequency: 5 interactions
- Maximum history in prompt: 20 items
- Maximum review length: 150 characters

## Usage

```bash
# Generate data
python prepare_llm_rec_data.py

# Verify data integrity
python verify_data.py
```

## Notes

1. **Title Quality**: Some titles may contain placeholders like `[title1]`, `[title2]`. These are from the LLM generation process and can be regenerated if needed.

2. **Review Truncation**: Reviews longer than 150 characters are truncated with "..." to keep prompts manageable.

3. **Rating Inclusion**: Ratings are included in the prompt to provide additional context about user preferences.

4. **For Fine-tuning**: This format is designed for LLM fine-tuning where the model learns to predict the next item title given user history.
